# Coordinate cross-entry restoration with explicit cycles

Store one active current-draft convergence cycle in additive v3.2 project state, preserve completed cycles and scope evidence as immutable history, and block parallel manuscript-changing cycles while retaining read-only inspection. Pending action remains operation-scoped instead of becoming a lifecycle owner. This chooses explicit cross-entry restoration over free strategy switching at stable operation gates, because creation and revision can otherwise stop after manuscript changes without restoring current-draft revision convergence.

Evaluate that state through deterministic disk and evidence checks combined with structured host semantic attestations. Schema validity alone cannot prove actual reading or editorial judgment, so only current satisfied evidence passes an entry or completion gate; missing or untrustworthy proof is indeterminate, while a known failed condition is not satisfied. Coordinated per-file verified writes and identity reconciliation replace any claim of a multi-file filesystem transaction.

Preserve each evaluation and its complete evidence graph as immutable history, including the tracker hash and all report, coverage, review, reader-state, revision execution, plan, batch, backup, no-edit, and attestation hashes. Exclude the active cycle and evaluation from that graph to prevent self-hashing. Revision execution separates preparation from verification: public operations validate existing author decisions, approvals, backup manifests and bytes, and current inputs before a write, then reread actual output bytes before marking execution verified. Earlier verified executions remain historical after later approved batches; only current pass and target bindings satisfy current findings. Completion first records the explicit author decision in the tracker, then recomputes and saves a new evaluation against the changed tracker hash, and only completes the cycle when that new evaluation remains satisfied. The prior evaluation remains unchanged.

The deterministic layer can verify identities, coverage structure, decisions, hashes, and attestation claims, but it cannot prove that a host actually read the text or that its editorial judgment is correct. Satisfied therefore remains bounded by trust in the recorded host and logical-reviewer attestations and by the recorded author decisions.

## Consequences

First-time creation needs an explicit bootstrap exception with a null starting scope and no claim that an empty manuscript has reached current-draft revision convergence. Its first committed publication links the batch and journal to the same cycle and continues through revise-draft for the initial full-manuscript evaluation. A first approved nonempty external import may instead provide publication evidence through manuscript reconciliation with a null previous scope and no creation commit, followed by the same initial full-manuscript revise-draft gate; cycle-external reconciliation still requires an explicit previous scope. Revise-increment is reserved for ordinary creation with a satisfied previous scope. Ordinary starts remain blocked until a real evaluator can supply a current satisfied starting evaluation. Active updates require a cross-process lock directory and an in-lock expected-revision check so independent CLI processes cannot overwrite one another. Leftover locks block later work for explicit recovery instead of being stolen. Later execution, review, evaluation, and completion operations reference the same cycle rather than creating strategy-owned state trees.

Independent local or narrowed revise-draft work may finish without a cycle and without a current-draft revision convergence claim. An independent full-manuscript recovery uses the same evaluator and immutable evaluation storage with `cycle_id: null`, so an unconverged project can establish a real satisfied starting point without inventing an unconverged starting scope or a parallel cycle. Accepted independent edits use explicit prepare/verify operations with the same approvals, backups, current-input checks, actual-output verification, lock, and execution storage as cycle-bound work; resolved findings cannot recover through a no-edit claim or an unverified status. A newer narrowed or unsatisfied independent evaluation blocks dependent entries until a later full-manuscript evaluation is satisfied; only unrestricted satisfied passes supply the inherited subcheck baseline. Active revise-draft recovery must use the active cycle instead. Read-only revise-fiction analysis and final review remain available without a cycle, while manuscript-changing or required-evidence-invalidating revise-fiction work retains its whole-book gates and restores current-draft revision convergence before completion.

External manuscript additions, modifications, deletions, and retained-path reorder transitions use one immutable manuscript reconciliation rather than caller-refreshed scope hashes. Exact tracker import decisions and real story-state sources bind current inventory and target identity. An active cycle derives its cumulative change set from the untouched starting snapshot, while an out-of-cycle reconciliation creates no cycle and can later join a provable previous scope to its target. Increment recovery requires a provable satisfied previous full-manuscript evaluation; unproven history is indeterminate and uses revise-draft. Empty inventory is never a satisfied scope or completion target, and nonempty recovery from empty always receives a full-manuscript revise-draft pass. Reconciliation, inventory, and latest story-state hashes enter subsequent evaluation evidence graphs, preserving invalidation rather than rewriting historical coverage or evaluations. The reconciliation operation writes no manuscript and does not replace existing backup, restore, approval, or execution checks.
