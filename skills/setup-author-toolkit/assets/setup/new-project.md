# New-project setup

Use this branch only when `<project-root>/.author-toolkit/project.json` is absent. Run `node <setup-skill-root>/scripts/inspect-root.mjs --project-root <project-root> --json` for bounded discovery, adding `--language-sample` when the author has not supplied a language. It returns entry-file and default component types, at most 12 candidate manuscript paths with an omitted count, and recursive historical regular-file counts without historical artifact paths. Use its entry-file results directly rather than pre-reading those files. Select from its candidate manuscript paths and default component types, using targeted checks only for an author-supplied path or an omitted candidate that needs disambiguation; if several plausible roots or manuscript paths exist, present the choices and let the author select one; do not enumerate historical artifact trees. Without `--language-sample`, discovery reads no file contents.

1. Select the project metadata, paths, and BCP 47 language. The project title is optional: use one already supplied by the author, or proceed directly with an empty title. With `--language-sample`, the CLI reads contents only when exactly one unomitted candidate exists, sampling its root file or the lexicographically first direct manuscript file with strict UTF-8 decoding and at most 300 Unicode code points without reading the whole manuscript. A non-unique or empty candidate selection returns no text; invalid UTF-8 is an explicit file-path error. Use a returned sample only to select a BCP 47 default. For Chinese, use `zh-Hans` for Simplified Chinese and `zh-Hant` for Traditional Chinese; use `zh` when Chinese is clear but no single script is established. Do not infer a regional tag such as `zh-CN` from a sample; preserve an author-supplied regional tag. Use `und` for mixed-language or otherwise inconclusive text. Register the detected or author-supplied language directly and report it in the final setup output.
2. Run `node <setup-skill-root>/scripts/setup-report.mjs capture --report-store <report-store> --kind scaffold -- --project-root <project-root> --language <selected-language>`, adding `--title <project-title>` and `--manuscript-root <selected-project-relative-path>` when supplied. Register selected existing paths as project-relative paths with `--story-bible`, `--audit-tracker`, `--reports`, `--sessions`, `--backups`, `--handoffs`, and `--creation`; omitted paths retain the template defaults. If argument clarification is needed, run `node <setup-skill-root>/scripts/scaffold-project.mjs --help`; treat its output as the argument contract instead of reading CLI source. The CLI reads the four sibling templates, uses one UTC timestamp for the manifest and new tracker, creates only missing directories and skeleton files, preserves existing manuscript and skeleton content, and refuses an existing manifest. For a newly created Story Bible, it writes a supplied project title to the `Title` field and otherwise leaves that field empty, retaining the neutral `# Story Bible` heading. Its built-in project validation gates the new manifest and skeleton files before entry-file installation. Stop on validation or filesystem failure; do not manually create state or repeat standalone validation after success.
3. Return to step 3 of `../../SKILL.md` for entry-file installation and the final diagnostic check. That check deliberately repeats project validation after entry-file installation and additionally verifies the entry files, status, execution recovery, and navigation cache. The report renderer reuses the paths returned by the captured scaffold command.

No current-draft revision convergence exists before the selected strategy establishes and verifies a scope. Do not infer eligibility for `revise-request` or a previous scope for `revise-increment` from new-project setup. When existing manuscript is registered, the final setup report must name the registered manuscript root and state that `revise-request` and `revise-increment` are not currently eligible because their required base scope or previous scope has not been verified. Offer `write-fiction` for continued creation, or `revise-draft` to establish the initial revision scope and reach current-draft revision convergence.
