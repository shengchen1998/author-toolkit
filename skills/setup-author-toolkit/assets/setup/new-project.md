# New-project setup

Use this branch only when `<project-root>/.author-toolkit/project.json` is absent. Run `node <setup-skill-root>/scripts/inspect-root.mjs --project-root <project-root> --json` for bounded discovery, adding `--language-sample` when the author has not supplied a language. It returns entry-file and default component types, at most 12 candidate manuscript paths with an omitted count, and recursive historical regular-file counts without historical artifact paths. Use its entry-file results directly rather than pre-reading those files. Select from its candidate manuscript paths and default component types, using targeted checks only for an author-supplied path or an omitted candidate that needs disambiguation; if several plausible roots or manuscript paths exist, present the choices and let the author select one; do not enumerate historical artifact trees. Without `--language-sample`, discovery reads no file contents.

1. Select the project metadata, paths, and BCP 47 language. The project title is optional: use one already supplied by the author, or proceed directly with an empty title. With `--language-sample`, the CLI reads contents only when exactly one unomitted candidate exists, sampling its root file or the lexicographically first direct manuscript file with strict UTF-8 decoding and at most 300 Unicode code points without reading the whole manuscript. A non-unique or empty candidate selection returns no text; invalid UTF-8 is an explicit file-path error. Use a returned sample only to propose a BCP 47 default; use `und` for mixed or inconclusive text, and ask the author to confirm a detected language before creating the project. An author-supplied language is already confirmed and needs no repeated confirmation in step 4 of `../../SKILL.md`.
2. Run `node <setup-skill-root>/scripts/scaffold-project.mjs --project-root <project-root> --author-project-root <setup-skill-root>/../author-project --language <selected-language> --json`, adding `--title <project-title>` and `--manuscript-root <selected-path>` when supplied. Register selected existing paths as they are with `--story-bible`, `--audit-tracker`, `--reports`, `--sessions`, `--backups`, `--handoffs`, and `--creation`; omitted paths retain the template defaults. The CLI reads the four sibling templates, uses one UTC timestamp for the manifest and new tracker, creates only missing directories and skeleton files, preserves existing manuscript and skeleton content, and refuses an existing manifest. For a newly created Story Bible, it writes a supplied project title to the `Title` field and otherwise leaves that field empty, retaining the neutral `# Story Bible` heading. Its built-in project validation gates the new manifest and skeleton files before entry-file installation. Stop on validation or filesystem failure; do not manually create state or repeat standalone validation after success.
3. Return to step 3 of `../../SKILL.md` for entry-file installation and the final diagnostic check. That check deliberately repeats project validation after entry-file installation and additionally verifies the entry files, status, execution recovery, and navigation cache. Reuse the paths returned by the scaffold command in the final setup report.

No current-draft revision convergence exists before the selected strategy establishes and verifies a scope. Do not infer eligibility for `revise-request` or a previous scope for `revise-increment` from new-project setup.
