# Workflow Reporting

Use this mode only when `write-fiction`, `revise-fiction`, `revise-draft`, `revise-increment`, or `revise-request` explicitly supplies an operation, confirmed `scope_id`, report path, versioned input list, language, and shared tracker path. Standalone calls retain finding v1 and their existing prose output behavior.

## Diagnostic boundary

Use the bounded `author-project read` projection, named inputs, and shared tracker. Apply the calling skill's diagnostic method within the requested scope and language. Record full, partial, or skipped coverage instead of presenting it as completed. Return findings and proposed creative changes without advancing `pending_action` or creating an approval. Switching among the five calling strategies at a stable operation gate does not change the scope or authorize a pending write. Creation operations keep their own artifact identity and never enter report v2 `stage`.

When the work produces a concrete manuscript edit, read `<setup-skill-root>/assets/references/context-fit.md` and complete its check before presenting the exact candidate for author review. A context-fit check does not approve a manuscript edit, expand its paths, or replace later review and evidence coverage.

Before writing a report or changing finding status, read the [controlled workflow terminology](terminology.md) and follow the applicable `Task-based reading` route in the `state-and-findings.md` reference identified by the calling orchestrator. The terminology defines shared names and boundaries; the state reference is the single source for the report envelope, stable IDs, tracker statuses, stale propagation, and shared evidence writes. Create the supplied report path through `author-project scaffold-report`; for current-scope manuscript inputs, use its stage preset and explicit scope selection to fill the deterministic envelope fields and recorded hashes. The CLI fills `skill.version` from the executing skill's installed declaration, supplies `findings: []` when that field is omitted, and validates the complete envelope before its create-only publication. Keep the report bound to the supplied scope ID and all actual input versions.

Deliver a report with findings or another author decision as context and stop through the author decision loop identified by that state reference in the calling orchestrator. For a shared `prose` operation, follow `prose-mechanics`' shared clean-audit continuation rule after the validated report, local evidence, and run index are persisted; do not create an author gate solely to ask whether to continue after a clean audit. For an approved manuscript batch, return the affected file list and exact approved output content to the calling `revise-fiction`, `revise-draft`, `revise-increment`, or `revise-request` orchestrator and wait for its backup confirmation. That orchestrator owns approvals, backups, publication, execution receipts, and restoration through `author-project`; the diagnostic skill does not write manuscript. `complete-write` publishes the supplied content, verifies outputs, and generates the execution receipt in one invocation.
